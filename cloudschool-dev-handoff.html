CloudSchool Design System

A production-ready design system for school/college/university ERP software. Built on a three-tier token architecture — primitives, semantic tokens, and component aliases. Everything references a token. Nothing is hardcoded.

200+
Design tokens across primitives, semantic colors, spacing, type, radius, elevation
50+
Components — Buttons, Forms, Cards, Tables, Badges, Modals, Tabs, Charts
2
Themes (dark + light) via single data-theme attribute on <html>
Important: All component styles use CSS custom properties. Never use hardcoded color hex values in your components — always reference a semantic token like var(--color-brand) or var(--text-primary).
Getting Started

Installation

The design system is delivered as standalone HTML/CSS. Copy the token block into your project's root CSS file, then import component styles as needed.

HTML
<!-- 1. Load fonts -->
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:wght@400;500;600&family=DM+Mono:wght@400;500&display=swap" rel="stylesheet">

<!-- 2. Add data-theme to html element -->
<html lang="en" data-theme="dark">

<!-- 3. Import foundation CSS -->
<link rel="stylesheet" href="cloudschool-foundation.css">
JS — Theme Toggle
function toggleTheme() {
  const html = document.documentElement;
  html.setAttribute('data-theme',
    html.getAttribute('data-theme') === 'dark' ? 'light' : 'dark'
  );
}
Foundation

Design Tokens

Tokens are organized in three tiers. Never reference primitive tokens in components — always go through semantic tokens.

Tier 1 → Primitive: Raw values. --primitive-neutral-900: #0f0f0f
Tier 2 → Semantic: Contextual meaning. --color-bg-deepest: var(--primitive-neutral-900)
Tier 3 → Component alias: Short-form. --brand: var(--color-brand)
CSS — Token Block (partial)
:root {
  /* ── Brand ─────────────────────────────── */
  --color-brand:        #3D52E5;
  --color-brand-hover:  #3246d3;
  --color-brand-alpha-20: rgba(61,82,229,0.18);
  --color-brand-alpha-10: rgba(61,82,229,0.10);

  /* ── Backgrounds ────────────────────────── */

  --color-bg-base:      #121212;
  --color-bg-canvas:    #171717;
  --color-bg-surface:   #1a1a1a;
  --color-bg-elevated:  #1f1f1f;
  --color-bg-overlay:   #242424;

  /* ── Borders ────────────────────────────── */
  --border-subtle:      #1e1e1e;
  --border-standard:    #2a2a2a;
  --border-prominent:   #363636;
  --border-focus:       var(--color-brand);

  --text-tertiary:      #6b6b6b;

Components

Cards

Cards use border-based depth, not shadows. Shadows are reserved for modals and floating elements. Never mix borders and shadows on the same card.

HTML — Stat card
<div class="stat-card">
  <div class="stat-label">Total Students</div>
  <div class="stat-value">4,821</div>
  <div>
    <span class="stat-delta up">↑ +8.2%</span>
  </div>
  <div class="stat-footer">vs last semester</div>
</div>
✓ Do
Use border: 1px solid var(--border-subtle) on cards. Stack cards on --bg-surface inside a --bg-canvas parent for elevation hierarchy.
✗ Don't
Add box-shadow to cards. Don't nest cards inside cards more than one level deep. Don't use --border-prominent on cards — it's too strong.

Modals

Modals use a blurred backdrop, scale-in animation, and a max-width of 480px by default. Always include a close button and ESC key handler.

HTML — Modal structure
<div class="modal-backdrop" id="myModal">
  <div class="modal">

    <div class="modal-header">
      <span class="modal-title">Title</span>
      <div class="modal-close"
           onclick="closeModal('myModal')">✕</div>
    </div>

    <div class="modal-body">
      <!-- content -->
    </div>

    <div class="modal-footer">
      <button class="btn btn-secondary"
              onclick="closeModal('myModal')">Cancel</button>
      <button class="btn btn-primary">Confirm</button>
    </div>

  </div>
</div>

<!-- JS -->
function openModal(id)  { document.getElementById(id).classList.add('open'); }
function closeModal(id) { document.getElementById(id).classList.remove('open'); }

// ESC to close
document.addEventListener('keydown', e => {
  if (e.key === 'Escape')
    document.querySelectorAll('.modal-backdrop.open')
      .forEach(m => m.classList.remove('open'));
});
Patterns

App Shell

The admin shell uses a fixed 240px sidebar, 56px topbar, and main-content with left margin. The student shell uses 220px. Never use absolute positioning for content — always margin-left on main-content.

CSS — Layout tokens
--sidebar-w: 240px;  /* admin */
--topbar-h:  56px;

.sidebar {
  width: var(--sidebar-w);
  position: fixed;
  top: 0; left: 0; bottom: 0;
  background: var(--primitive-neutral-900);
  border-right: 1px solid var(--border-subtle);
  z-index: 100;
}
.main-content {
  margin-left: var(--sidebar-w);
  flex: 1;
}
/* Mobile: sidebar becomes overlay */
@media (max-width: 768px) {
  .sidebar { transform: translateX(-100%); }
  .sidebar.open { transform: translateX(0); }
  .main-content { margin-left: 0; }
}
Patterns

Theming

Light/dark mode is implemented via data-theme on the html element. Semantic tokens remap — primitives never change. Component code never needs to change between themes.

CSS — Light mode override
[data-theme="light"] {
  --color-bg-base:    #f4f4f5;
  --color-bg-surface: #ffffff;
  --text-primary:     #09090b;
  --text-secondary:   #52525b;
  --border-subtle:    #e4e4e7;
  --border-standard:  #d4d4d8;
  /* Brand color never changes */
  /* --color-brand stays #3D52E5 */
}
Rule: Never use --primitive-neutral-* tokens directly in components. If a surface needs to stay dark in light mode (e.g. sidebar), use the hardcoded primitive — not a semantic token that flips.

Motion

Motion is purposeful, not decorative. Use the defined duration scale and easing curves — never custom values.

TokenValueUse
--dur-fast120msHover states, color transitions, badge changes
--dur-std220msSidebar active, modal backdrop, toast in
--dur-slow380msPage transitions, modal scale-in, panel slide
--ease-outcubic-bezier(0.16,1,0.3,1)Elements entering the screen (decelerating)
--ease-in-outcubic-bezier(0.4,0,0.2,1)Toggles, theme switches, state changes

@keyframes pageFadeIn {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}
.view-enter {
  animation: pageFadeIn var(--dur-slow) var(--ease-out) both;
}

Accessibility

All components must meet WCAG 2.1 AA. Key requirements for CloudSchool components:

4.5:1
Text contrast ratio
--text-primary (#f0f0f0) on --bg-base (#121212) = 14.6:1 ✓
44px
Minimum touch target
All interactive elements must be ≥44px in at least one dimension on mobile
3px
Focus ring width
box-shadow: 0 0 0 3px var(--color-brand-alpha-20) — visible on all backgrounds
Color alone rule: Never use color as the only differentiator. All status badges include a text label in addition to color. The dot variant is additive — the label is always present.
HTML — Focus + ARIA pattern
<!-- Required for icon-only buttons -->
<button class="icon-btn"
        aria-label="Open notifications"
        title="Notifications">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Required for form inputs -->
<label for="student-email" class="form-label">
  Email
</label>
<input id="student-email"
       class="form-input"
       aria-describedby="student-email-error"
       aria-invalid="false">
<span id="student-email-error"
      class="form-error"
      role="alert">
  Please enter a valid email.
</span>
